# FunPay → Telegram Notifier (multi-tenant)

Telegram-бот, который любой FunPay-продавец может подключить к своему аккаунту: получать уведомления о новых сообщениях и заказах, включать автоответчик, смотреть статистику и приглушать спамеров.

Версия **multi-tenant** — один экземпляр бота обслуживает любое количество пользователей. Каждый пользователь привязывает свой `golden_key` через Telegram-команду; ключи хранятся в SQLite в зашифрованном виде (Fernet / AES-128 + HMAC-SHA256).

Если тебе нужна простая «личная версия для одного аккаунта» — смотри тег `v0.1.0`.

## Возможности

Per-user:

| Что | Команда / источник | Комментарий |
|---|---|---|
| Подключить FunPay-аккаунт | `/setkey <golden_key>` | бот валидирует ключ и сразу запускает раннер |
| Задать User-Agent | `/setua <ua>` | рекомендуется — снижает риск разлогинов |
| Уведомление о новом сообщении | автоматически | ник, ссылка на чат, текст |
| Уведомление о новом заказе | автоматически | ник, лот, категория, сумма, ссылки |
| Уведомление о смене статуса заказа | автоматически | оплачен / закрыт / возврат |
| Уведомление о падении сессии FunPay | автоматически | если протух `golden_key`, словил 403 и т.п. |
| Автоответчик | `/autoreply on\|off\|set <текст>\|show` | отвечает один раз каждому новому собеседнику |
| Статистика | `/stats` | сообщения и заказы за 1 / 7 / 30 дней |
| Приглушить пользователя | `/block <ник>`, `/unblock <ник>`, `/blocked` | уведомления от этого ника не приходят |
| Статус | `/status` | баланс, активные продажи/покупки, состояние автоответчика и раннера |
| Пауза | `/pause`, `/resume` | останавливает / запускает раннер |
| Удалить себя | `/unlink` | удаляет `golden_key` и всю статистику этого пользователя из БД |

Админ (если задан `ADMIN_TG_USER_ID`):

| Команда | Что делает |
|---|---|
| `/admin` | сводка: сколько всего пользователей, сколько активны, какие раннеры запущены |

## Установка (хост)

Нужен Python **3.11+**.

```bash
git clone <repo-url>
cd <repo-dir>

python -m venv .venv
source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -e .
```

Сгенерируй ключ шифрования:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Скопируй `.env.example` → `.env` и заполни:

```
TELEGRAM_BOT_TOKEN=<токен от @BotFather>
ENCRYPTION_KEY=<вывод команды выше>
ADMIN_TG_USER_ID=<твой telegram id, узнаётся у @userinfobot — необязательно>
```

Запусти:

```bash
python -m funpay_tg_notifier
```

Бот начнёт принимать `/start` от любого пользователя.

### Автозапуск (systemd)

`/etc/systemd/system/funpay-tg-notifier.service`:

```ini
[Unit]
Description=FunPay → Telegram notifier (multi-tenant)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=funpay
WorkingDirectory=/opt/funpay-tg-notifier
ExecStart=/opt/funpay-tg-notifier/.venv/bin/python -m funpay_tg_notifier
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now funpay-tg-notifier
journalctl -u funpay-tg-notifier -f
```

## Пользовательский флоу (что увидит обычный человек)

1. Открывает твоего бота в Telegram → `/start`.
2. Получает инструкцию: как достать `golden_key` из DevTools браузера.
3. Отправляет `/setkey ABC123...`.
4. Бот валидирует ключ, шифрует и сохраняет в БД, запускает FunPay-раннер.
5. Получает «✅ Подключён аккаунт <ник>».
6. Дальше уведомления капают сами; команды описаны выше.

**Важно для пользователя:** Telegram-боты в личке не могут удалять сообщения собеседника. После `/setkey` пользователь должен удалить своё сообщение с ключом руками. Бот про это пишет в ответе.

## Как это работает

- **Регистр раннеров**: на каждого Telegram-пользователя поднимается отдельный поток с `FunPayAPI.Runner.listen()`. Поток ходит на FunPay каждые `FUNPAY_POLL_DELAY` секунд (по умолчанию 6).
- **Asyncio loop** с aiogram крутится в основном потоке; события из FunPay-потоков прокидываются в loop через `run_coroutine_threadsafe`.
- **БД**: SQLite, все таблицы партиционированы по `tg_user_id`.
- **Шифрование**: `golden_key` хранится в `users.golden_key_enc` (Fernet). Расшифровка возможна только при наличии `ENCRYPTION_KEY` в `.env`.
- **Автовосстановление**: при старте бот читает всех `enabled` пользователей и запускает их раннеры.
- **Падение раннера**: если FunPay вернул ошибку (например, `golden_key` протух), пользователю в Telegram приходит алерт; раннер пытается переподключиться каждые 30 секунд. После релогина в браузере достаточно прислать новый `/setkey`.

## Безопасность

- Хранение чужих `golden_key` = доступ к чужим FunPay-аккаунтам. Это серьёзная ответственность. Сделай минимум:
  - **Backup `.env`** (если потеряешь `ENCRYPTION_KEY` — ни один сохранённый ключ не восстановить).
  - Ограничь доступ к серверу и БД (`chmod 600 data/funpay_tg.db`).
  - **Не клади `.env` в git** (он уже в `.gitignore`).
  - Подумай про публичную политику использования, особенно если хостишь не только для себя.
- `/setkey` валидирует ключ через одиночный запрос к FunPay. Если ключ невалидный — в БД ничего не пишется.
- Пользователь может в любой момент сделать `/unlink` — все его данные стираются.

## Лимиты и масштабирование

- Один FunPay-раннер ≈ 1 поток + 1 keep-alive соединение. На VPS 1 vCPU / 1 ГБ RAM комфортно живут ~50–100 одновременных пользователей.
- Один Telegram-бот = 30 сообщений/сек на всех пользователей. До нескольких сотен активных пользователей нормально, дальше нужен throttle.
- Если планируешь >500 пользователей — переноси раннеры в отдельный пул процессов (`multiprocessing`) и шарди БД.
